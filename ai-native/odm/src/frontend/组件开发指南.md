# 组件开发指南

## 📋 概述

本文档提供开发组件库中各个组件的详细指南。所有组件都将作为工作台窗口组件使用，需要遵循统一的接口和设计规范。

## 🏗️ 组件架构

### 组件类型分类

根据 `SBOMIde.vue` 中的定义，组件分为三类：

#### 1. **客户选配组件** (customerSelectionItems)
- `requirement-discussion` - 需求讨论
- `model-selection` - 型号选择

#### 2. **服务工具组件** (serviceToolItems)
- `ai-guide` - AI 智能导购
- `3d-model` - 3D 模型展示
- `product-params` - 产品手册

#### 3. **研发工具组件** (devToolItems)
- `design-diff-table` - 设计差异表
- `doc-change` - 文档变更

## 📐 组件接口规范

### Props 定义

所有组件必须接收 `item` prop：

```vue
<script setup>
defineProps({
  item: {
    type: Object,
    default: () => ({})
  }
})
</script>
```

### item 对象结构

```javascript
{
  instanceId: 'inst-1234567890-abcde',  // 实例唯一ID
  type: 'product',                      // 组件类型
  title: '需求讨论',                    // 显示标题
  originalId: 'requirement-discussion'  // 原始组件ID
}
```

### 组件注册

在 `SBOMIde.vue` 中需要：

1. **导入组件**（第804-808行）：
```javascript
import RequirementDiscussionWindow from '../../components/RequirementDiscussionWindow.vue'
import ModelSelectionWindow from '../../components/ModelSelectionWindow.vue'
// ... 其他组件
```

2. **注册到组件映射**（第1005-1011行）：
```javascript
const componentMap = {
  'product': ProductWindow,
  'calculator': CalculatorWindow,
  'ai-assistant': AiAssistantWindow,
  '3d-viewer': Viewer3DWindow,
  'product-params': ProductParamsWindow,
  // 新增组件
  'requirement-discussion': RequirementDiscussionWindow,
  'model-selection': ModelSelectionWindow,
  // ...
}
```

3. **添加图标映射**（第988-998行）：
```javascript
function getWindowIcon(instanceId) {
  const item = getProjectItem(instanceId)
  if (!item) return 'fa-solid fa-bolt'
  
  let iconClass = 'fa-solid fa-bolt'
  // 现有映射...
  if (item.type === 'requirement-discussion') iconClass = 'fa-solid fa-comments text-blue-500'
  if (item.type === 'model-selection') iconClass = 'fa-solid fa-list-check text-green-500'
  // ...
  return iconClass
}
```

## 🎨 设计规范

### 1. 布局结构

所有组件应遵循以下基本结构：

```vue
<template>
  <div class="h-full flex flex-col">
    <!-- 头部区域（可选） -->
    <div class="mb-4">
      <h2 class="text-lg font-bold">{{ item?.title || '标题' }}</h2>
    </div>
    
    <!-- 主要内容区域 -->
    <div class="flex-1 overflow-y-auto">
      <!-- 组件具体内容 -->
    </div>
    
    <!-- 底部操作区（可选） -->
    <div class="mt-4 pt-4 border-t border-gray-200">
      <!-- 操作按钮等 -->
    </div>
  </div>
</template>
```

### 2. 样式规范

- **颜色主题**：使用 Tailwind CSS 类，保持与系统一致
- **字体**：
  - 标题：`text-lg font-bold`
  - 正文：`text-sm`
  - 小字：`text-xs`
  - 等宽字体：`mono-font`（用于代码、数据）
- **间距**：使用 Tailwind 的间距系统（p-4, mb-4, gap-2 等）
- **圆角**：`rounded` 或 `rounded-lg`
- **边框**：`border border-gray-200` 或 `border border-gray-300`

### 3. 响应式设计

- 组件内容应适配窗口大小
- 使用 `overflow-y-auto` 处理内容溢出
- 表格和列表应支持横向滚动（如需要）

## 📝 组件开发步骤

### 步骤 1: 创建组件文件

在 `src/frontend/src/components/` 目录下创建组件文件：

```
RequirementDiscussionWindow.vue
ModelSelectionWindow.vue
DesignDiffTableWindow.vue
DocChangeWindow.vue
```

### 步骤 2: 实现基础结构

```vue
<template>
  <div class="h-full flex flex-col">
    <div class="flex-1 overflow-y-auto p-4">
      <!-- 组件内容 -->
    </div>
  </div>
</template>

<script setup>
defineProps({
  item: {
    type: Object,
    default: () => ({})
  }
})
</script>

<style scoped>
/* 组件特定样式 */
</style>
```

### 步骤 3: 实现业务逻辑

根据组件功能实现具体业务逻辑：

- **数据获取**：使用 `item.originalId` 区分不同实例
- **状态管理**：使用 Vue 3 Composition API (`ref`, `reactive`, `computed`)
- **API 调用**：如需要，使用 `fetch` 或 `axios`

### 步骤 4: 注册组件

在 `SBOMIde.vue` 中完成注册（见上方"组件注册"部分）

### 步骤 5: 测试

1. 从组件库拖拽或点击组件
2. 验证组件正确显示
3. 测试交互功能
4. 验证多实例是否独立工作

## 🎯 各组件开发建议

### 1. 需求讨论 (requirement-discussion)

**功能**：客户需求讨论与确认

**建议实现**：
- 聊天/讨论界面
- 需求列表展示
- 添加/编辑需求项
- 需求状态管理（待确认/已确认/已拒绝）

**UI 建议**：
- 左侧：需求列表
- 右侧：详情/编辑区
- 底部：添加新需求按钮

### 2. 型号选择 (model-selection)

**功能**：产品型号选择

**建议实现**：
- 型号列表（卡片或表格）
- 筛选功能（按类别、功率等）
- 型号对比功能
- 选择确认

**UI 建议**：
- 网格布局展示型号卡片
- 每个卡片显示：型号名、关键参数、推荐标签
- 支持多选和对比

### 3. 设计差异表 (design-diff-table)

**功能**：BOM设计差异对比

**建议实现**：
- 差异表展示（表格形式）
- 筛选（新增/变更/删除）
- 导出功能
- 差异详情查看

**UI 建议**：
- 表格布局
- 颜色标识：新增（绿色）、变更（黄色）、删除（红色）
- 支持排序和筛选

### 4. 文档变更 (doc-change)

**功能**：文档变更记录

**建议实现**：
- 变更记录列表（时间线或表格）
- 变更详情查看
- 版本对比
- 变更审批流程

**UI 建议**：
- 时间线布局或表格布局
- 显示变更人、时间、类型、状态
- 支持查看变更前后对比

## 🚀 开发优先级建议

建议按以下顺序开发：

1. **需求讨论** - 核心功能，使用频率高
2. **型号选择** - 核心功能，使用频率高
3. **设计差异表** - 重要功能，数据展示为主
4. **文档变更** - 重要功能，记录查看为主

## 💡 最佳实践

1. **组件复用**：提取公共逻辑和样式
2. **性能优化**：大数据量使用虚拟滚动
3. **错误处理**：添加错误边界和提示
4. **可访问性**：添加适当的 ARIA 标签
5. **代码规范**：遵循项目代码风格
6. **文档注释**：为复杂逻辑添加注释
